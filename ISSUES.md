## B2 — a screen left on counts as use

**Accepted limitation (Lucas 2026-11-02; Codex: no rule 9, cap while charging 6, cap always 3):**
AppTime counts the app in front while the screen is on — attention cannot be seen without touches,
and no public API reports them. Any cut-off undercounts a long video or read. The sighting
(Instagram 04:00–09:25 while Lucas slept) came from `stay_on_while_plugged_in=7`, set for adb: that
block was removed from his data and the setting is back to 0. Keep it 0 outside a screenshot run.

## B4 — totals inflated by B3 are still stored

Phone and app totals counted before `1d82611` (restarts replayed time already counted) were not
repaired; days up to 2026-11-05 may read high in the 30-day usual.

## B6 — a USB install on MIUI needs someone at the phone

**Accepted limitation (Lucas 2026-11-06):** MIUI asks on screen before each `adb install`; a missed
prompt fails with `INSTALL_FAILED_VERIFICATION_FAILURE` and a retry only asks again, so no script
gets past it. The way around is in [SETUP.md](SETUP.md) § Install on a phone. A bare
`./gradlew testDebugUnitTest` also runs `:url_launcher_android`'s own failing tests: run
`make verify-full`, which runs `:app:testDebugUnitTest` only.

## B7 — tuned on one phone

Every device check ran on one Redmi Note 10 Pro (MIUI 14 / HyperOS). AppTime targets any Android 6+,
so each value below holds there and is unknown elsewhere:

- **Pill geometry**: `OverlayPlacement.ICON_ROW_FROM_BOTTOM_DP` (12 dp, Xiaomi's cutout band); text
  13 dp to match the HyperOS clock; the fit ladder's widths come from this phone's Roboto; the
  font-scale steps in `TimerOverlay` were measured on HyperOS.
- **Theme guess**: `ChipShade.knownDark` lists only MIUI Recents; other launchers' Recents are untested.
- **App lists**: `isSystemPkg` / `isLauncherPkg` (`lib/utils/app_info.dart`) name MIUI packages but
  few Samsung, Oppo, Vivo, Huawei or Motorola ones; a vendor's system app may show up as a user app.
- **Autostart**: only MIUI's screen is opened; other skins with their own background killers
  (Huawei, Oppo, Vivo, Samsung's sleeping apps) fall back to the app details page.
- **UsageStats**: `queryEvents` keeps ~9 days here (seed 2026-11-06 reached 2026-10-28 12:51);
  app-switch latency and the retention are unmeasured elsewhere. The seed holds 9 days, not 30.

Next step: a stock-Android emulator pass (Pixel image) for the first four; a second physical
brand before the Play release.

## B9 — the session at 04:00 and the time zone

At the 04:00 rollover `MonitoringService.tick` drops the open session from the totals and the
session log alike, and neither stores the time zone, so a trip re-reads past hours in the new one
(panel 2026-11-06). Both predate the log; the fix splits the session at the boundary.

## B8 — two prune windows

Dart prunes at 90 days (`storage_service_queries.dart` `pruneOldData`), Kotlin at 31
(`MonitoringService.pruneOldData`), and Kotlin runs daily, so 31 wins; README/CONTEXT still say 90.
One owner and one number is the fix; the session log follows Kotlin's 31 meanwhile.
